Not a bug; the user considered requiring an explicit answer or dismissal and declined it twice.
- **Conflict heuristic tuning:** `CONFLICT_TOPIC_OVERLAP` (0.5) also applies to statements with equal figures, on purpose (over-flag rather than miss). If a demo shows too many conflicts for restatements, raise the overlap to 0.6 or require a differing word when the figures are equal.
- **Prompt and behavior observations, not yet acted on:** the agent sometimes adds an effective date the user did not state; `gpt-5.6-luna` once miscounted in a confirmation ("6 claims across 6 fields" while listing 5), and putting the active claim count in the state item would make counts reliable. Re-run the eval after any prompt change.
- **A real gap the manual test surfaced (2026-09-27), not yet decided:** the same fact can end up recorded near-identically under two or three different fields (e.g. an authorization limit stated once in `roles`, again in `authorization`, again inside a `procedure` step), each with its own confirm/reject state, which reads as repetitive in the final SOP. Not addressed; no decision yet on whether it is worth deduplicating across fields.
- **Two more gaps an outside reviewer (asked to grade a live SOP output) surfaced on 2026-09-27, both real, neither in the consistency review's scope:**
  - **Interview depth within one step.** The consistency review only checks relationships between already-recorded facts; it has no way to say "this one step is too thin, ask what data it actually captures" (e.g. "the operator submits a maintenance request" with no mention of what fields that request needs). Nothing today prompts the agent to probe a single vague step for more operational detail — this would have to be a different mechanism (a prompt rule, or a new deterministic check), not an extension of the existing category list.
  - **Section order is fixed regardless of domain-specific importance.** `SOP_FIELD_NAMES` (`purpose, scope, trigger, roles, procedure, authorization, completionCriteria, governance, exceptions, evidence, controls, decisionRules, prerequisites`) is a single constant order for every SOP; `buildSopDocument` never reorders it by content. A safety-critical rule that would need to appear first in this specific process (e.g. "stop the line immediately") always prints wherever its field sits in that fixed list (here, inside `decisionRules`, near the end) — there is no mechanism to promote a claim to appear earlier because of what it says. Fixing this would mean either a per-session priority signal, or accepting that a person reorders content themselves after export.
- **Researched 2026-09-27: how this compares to real SOP standards, and decided it is a soft area, not addressed now.** EPA QA/G-6 (the most concrete public SOP format standard) gives technical SOPs a fixed element order — Scope, Summary of Method, Definitions, **Health and Safety Warnings, Cautions, Interferences**, Personnel Qualifications, Equipment/Supplies, Procedure, Data/Records Management, Quality Control, References — with safety warnings as their own section, structurally guaranteed to sit before the procedure, and equipment/qualifications (this app's `prerequisites`) also placed before the procedure, not treated as optional. This app has neither: no dedicated safety field (safety content only ever lands in `decisionRules`, an advisory field near the end of a fixed order), and `prerequisites` is advisory rather than pre-procedure-required. Separately, ISO 9001 itself mandates no fixed section list at all, leaving structure to the organization — so there is no single "the industry requires this" answer, only EPA's more concrete convention. Decided: this is a soft gap, not fixed now, because (a) EPA's own guidance frames safety warnings as required "when applicable," matching this app's stance that not every process has a safety dimension; (b) fixing either gap for real needs a new field or a schema-wide reordering, touching session schema, `computeGaps`, `interviewAgenda`, `sopDocument`, the PDF renderer and every existing eval scenario — comparable in scope to a full slice, not a tweak; (c) this project is graded on the agent's interview and gap-finding behavior, not on template conformance to a specific regulatory SOP standard. Revisit if this is ever pitched to a customer in a safety- or compliance-heavy industry, where a missing dedicated safety section would be a real defect, not a cosmetic one.
- **Clarified 2026-09-27 (mechanism, not a bug): a consistency review can queue up to 4 findings from one model call, but only offers one per turn.** If the person keeps chatting at all after the first question — even about something unrelated — the next unoffered finding from the same stored review surfaces on the very next turn, with no new model call needed (a new model call only reruns when the recorded claims actually change). The finding that went unanswered in the equipment-maintenance test was not stuck; the interview simply never continued past that one turn — the person went straight to the review panel instead of sending another message.

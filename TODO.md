## Next up / backlog

- **Finish slice 5:** re-run `pnpm eval` (see Status), then commit in scoped groups on the user's go-ahead, and push only on a separate go-ahead.
- **Slice 6, hardening and handoff:** rate limiting is now urgent for `POST /documents/extract` (the first unauthenticated route that spends model money, ahead of `/chat`); a hard timeout for a parser that never returns (a worker thread with a lifetime, then terminate); deployment (Vercel web, Render API), CORS for the deployed origin, the README and the demo script. Provider-neutral error types remain an accepted weak spot.
- **Known limit, found by Codex round 3 (P1, accepted):** two uploads with the same sanitized file name count as one source, so contradictory rules in a revised file with the same name never become a conflict (that rule exists so a handbook's own $500/$5,000 ladder is not flagged). Fixing it needs an upload identity in the citation (schema v6, the browser generates one id per upload). **Decided 2026-09-20: not fixed in v1** (single-user, single-session, local; a same-name file with different content is unlikely). Revisit if a demo needs a revised file.
- **Conflict heuristic tuning:** `CONFLICT_TOPIC_OVERLAP` (0.5) now also applies to statements with equal figures, on purpose (the user chose to over-flag rather than miss). If the eval or a demo shows too many conflicts for restatements, raise the overlap to 0.6 or require a differing word when the figures are equal. A disagreement worded very differently is still missed (the claim stays `extracted`, an open gap).
- **Prompt and behavior observations, not yet acted on:** the agent sometimes adds an effective date the user did not state; `gpt-5.6-luna` once miscounted in a confirmation ("6 claims across 6 fields" while listing 5); putting the active claim count in the state item would make counts reliable, and it matters more now that an upload can add many claims at once. Re-run the eval after any prompt change.
- **Possible polish:** one click per suggestion or per extracted claim may be too many in a demo (a per-field tick is a `checkFinalization` change); the approval panel lists suggestions but does not jump to them; if the agent tells the user to "withdraw the confirmation" and they do not find the button, add a hint in the panel; a second upload of the same file costs one model call before the duplicate check drops its claims (hashing the file in the session was left out); upload progress is a busy label, not a bar; a PDF font that draws non-Latin text is the recorded upgrade path (decision 36).
